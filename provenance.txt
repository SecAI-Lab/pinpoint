Data Provenance

artmeta asks how the packaged data was collected, where, and when. The artifact
ships static-analysis output only; no source code and no binaries are
redistributed.

Where:
- Nine open-source projects, taken from their public release lines: binutils,
  coreutils, jasper, libarchive, libjpeg-turbo, libming, libtiff, libxml2 and
  zziplib. license.txt lists the license for each.
- 73 publicly disclosed CVEs, all fixed upstream years ago. For each we read the
  security patch diff by hand to identify the root-cause function, yielding 74
  functions across 12 CWEs.
- The packaged subset covers five of the nine projects and 22 of the 73 CVEs:
  32 target binaries against reference databases of 139 and 81 entries.

How (build):
- Compiled from unmodified upstream source with both GCC and Clang.
- Targets: -O1, -O2, -O3. -O0 is excluded because without optimization the
  compiler does not inline.
- References: -O0 through -O3, so a target can match a reference from any
  optimization level.
- For vulnerabilities showing Types II-IV, additional -fno-inline builds serve
  as boundary-preserving references. References only; targets are always the
  default builds.

How (extraction, all offline):
- Ghidra 11.4's headless analyzer recovers functions, basic blocks and the
  block-to-instruction mapping, to which BinShot's operand-normalization rules
  are applied. radare2 does the equivalent for SAFE, which does not consume
  Ghidra output.
- pyelftools reads DWARF metadata for which functions were inlined into which,
  and the byte ranges the inlined bodies occupy. This is the ground truth, and
  the reason the binaries carry debug information.
- Each vulnerability-relevant function is labelled with one of the four inlining
  types of Section III, derived from those DWARF relationships.
- This leaves 596 vulnerability-relevant target-function instances and a
  577-entry reference database, plus 409 -fno-inline references.

Subset selection:
- artifact/scripts/build_eval_subset.py carries the rule and the frozen result;
  build_safe_subset.py does the same for the SAFE representation.
- The rule reads only the inlining type, the project and the measured runtime,
  never whether PinPoint ranked or localized a case correctly.

When:
- The corpus was compiled and analyzed, and the ground truth extracted and
  verified, between March and August 2026.
- The packaged subset was derived in September 2026.
